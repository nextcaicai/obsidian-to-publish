# 微信公众号排版对应关系

本表记录当前公众号 profile 输出的样式，作为排版讨论基线，不代表已完成微信公众号编辑器的真实粘贴验收。字号单位为 CSS px，不是印刷字号；Obsidian 主题中的字号不会原样同步，复制时会套用平台规则。

规则入口：`src/platforms/profiles.ts` 的 `PLATFORM_PROFILES.wechat`。复制与官方草稿接口共用此 profile；草稿接口还会额外清理 HTML、将代码块中的换行转换为 `<br>`。

| --- | --- | --- |

| 二级标题 `##` | 20px、粗体、行高 1.45、`#1d2129` | 上 1.8em、下 0.8em；无边框 |

## 当前缺口，留待讨论

- 四、五、六级标题共用一种样式，没有完整六级视觉层级。
- 加粗写死为 16px：标题内的加粗文字可能比标题本身小。引用内的加粗颜色也会覆盖引用灰色。
- 嵌套列表没有专门的逐层字号、符号、缩进与间距规范，依赖原生嵌套结构及相同列表规则。
- Callout 类型没有分别设计：note、warning 等共用同一种外观。
- 高亮、删除线等尚未形成完整的平台样式规范。
- 代码块有基础底色和字体，没有独立的公众号语法高亮配色规范。
- 正文、标题的段前段后间距使用 em，随字号变化；尚未形成统一的间距尺度。
- 部分未被 profile 覆盖的样式仍可能来自 Obsidian 主题。关闭“内联样式”时，这些样式也可能不同。

## 列表修复的验证边界

列表容器、列表项和同一段的行内内容显式设为 16px；同一段的加粗、普通文字、链接和行内代码放入一个 span，覆盖导入的行内文字块布局。行内代码仍按代码规则缩小。多段落、嵌套列表、引用和代码块保留各自结构。

自动化用例覆盖紧凑/宽松列表、混合行内文字、嵌套编号、代码与图片、任务标记及草稿接口后续清理。最终仍需在开发 vault 重载插件，复制实际文章到公众号编辑器，检查拆行、字号和编号。
